## 1. The operating loop (every slice runs this way)

1. **Spec** — the lead specs the slice from the work order and roadmap, with acceptance criteria written before code.
2. **Build** — Opus builder subagents implement. Builders never review their own work.
3. **Review, three ways** — an independent adversarial reviewer subagent attacks the diff; the lead reviews everything; the push to the PR triggers hosted **Codex review** on GitHub — the cross-platform brain check (two different model families reading the same diff).
4. **Field test** — Adam runs the installed plugin on real builds in his other projects (the Rooms pattern). The receipts and host-surface evidence come back to this session for evaluation. **The plugin in the field is the delivery vehicle and the test harness at once.**
5. **Gate** — a slice is done when its field gate passes, not when CI is green. This rule exists because of finding F2: the project has already been burned once by green checks that proved nothing about the runtime.

Roles, standing: *The builders produce (Opus subagents here; Codex in the field). The evaluators examine (adversarial subagents, hosted Codex review, blind readers). Lyhna witnesses (the plugin on Adam's real builds). Adam decides.*

### CZ-14 — Seal-as-you-go (checkpoint anchors)
Adam's decision (2026-07-22): checkpoint anchors over an operator-close command. A checkpoint anchor written at every Stop makes any run a verifiable packet at its last checkpoint; the receipt face states its lifecycle in observational vocabulary only (`SEALED`; close-requested-but-not-sealed with the deferred-close blockers surfaced as observations; or `OPEN` as of event N with no close request observed); open packets verify with the same hash-chain discipline seals use. Constraints: deterministic, zero new dependencies, additive schema, legacy runs read exactly as before.
**Field gate:** an open (unsealed) packet handed cold to a blind reader verifies and states its own lifecycle honestly, with no inferred completion; and with CZ-14 installed, the three (now four) stuck-open field runs become verifiable packets at their last checkpoints.

> **Build record (2026-07-22).** Code complete at `4aff37d`, v0.1.27, 81/81 tests (63 inherited + 18 new CZ-14 fixtures), validator green; PR #3. The loop ran as designed. ### CZ-15 — report a check that could not run (2026-07-26)

> **Build record (2026-07-26).** Code-final at `bdf8eff`, v0.1.31, **129/129** (125 inherited, 4 new), validator green; PR #10, merged as `539e67f`, released as v0.1.31.
>
> **Found by using the product on itself.** The published v0.1.30 bundle was installed cold — no repo, no git above it, no `npm install`, isolated data root — and driven through a real two-window lineage chain with the bundle's own code. The bundle passed every structural check. What the tampered comparison exposed was the *report*: a clean run printed ten rows, a tampered run printed nine. `prior_continuation_refolds` had not failed, it had **disappeared**, with nothing stating it was never evaluated. Four gates dropped rows this way. The verdict was never wrong — a broken chain fails on its own — but "we could not check this" silently read as "this did not apply," which is the `UNRESOLVED_EVIDENCE` collapse one layer up, and a reader diffing two reports saw a row vanish instead of a reason.
>
> Fixed at `448179e` (127/127) by emitting a **fixed sequence**: recorded results in place, `NOT RUN` plus a reason for everything that never got there, constant row count regardless of outcome. `NOT RUN` carries `ok: false` and the verdict requires every check to have actually `PASS`ed, so an unknown fails safe even if a future path reaches it without an accompanying failure.
>
> **First change to go through an independent agent review against `SPEC.md` before merge** — a fresh session in a detached worktree, with no stake in the change landing. Verdict: SOUND WITH NITS, no blocking defect; it re-ran both gates, probed 14 adversarial inputs without finding a short or reordered row set, and confirmed the fail-safe claim by injecting a `NOT_RUN` on an otherwise all-PASS path. Two should-fixes were real and closed at `bdf8eff`. The larger one: **the SPEC clause this build added claimed more than the code delivered.** "Every lineage report carries every check" was falsified by a one-byte truncation, because a malformed `continuation.json` threw out of `verifyLineage` — costing not just that hop's rows but every hop after it. On a three-packet chain, tampering with the first packet meant packets two and three were never checked at all. That is this build's own defect one level up: dropping a row lets "could not check" read as "did not apply"; throwing drops the whole report. Reading a packet is total now — missing, empty, malformed, or wrong-shaped files are recorded FAILs. The second: `finalize` projected the sequence onto the recorded results, so a check recorded under an unregistered name vanished from both report and verdict — including a FAIL, returning `LINKED` on a packet that failed.
>
> The review also caught that the **tests were weaker than they read**: both assertions compared the report against a baseline built from the same `CHECK_SEQUENCE`, proving only that the two agreed. Deleting a check from that constant kept the suite green. The row set is pinned as literals now.
>
> Theme, and it is the one Slice B and CZ-14 reached from the other side: **an unknown is not a pass, and silence about a gap reads as absence of a gap.** The ledger arc established that a cache must never select a weaker verification path; this establishes that a report must never let an unevaluated check pass for an inapplicable one.

> **Honesty note on the records above (2026-07-26).** The #6–#9 records were compiled after the fact from commits, diffs, and PR bodies — not written at build time by the sessions that did the work, as every record above this point was. Test counts and file statistics were re-verified by checking out each commit and running the suite. What is **not** attested is the hosted-review detail the earlier slices record round by round: this session did not witness those rounds and has not invented them. Where a PR ran review, its body is the primary record. The distinction is the point — a record that reads uniformly with the ones above it while resting on weaker evidence would be the overclaim this plan exists to prevent.

## 3. Standing rules

- One live edge at a time; a slice ships only when the one below passed its field gate.
- The honesty ceiling is constitutional in every slice; the permission vocabulary is banned from schemas and surfaces.
- Blind at the boundary, never at the eyes: disclosure is tiered at export; capture is never impoverished to make export easier.
- Every slice's evidence (field receipts, blind reads, Codex reviews) is appended to the review record so no future session has to re-derive this.

*The builder produces. The evaluator examines. Lyhna witnesses. The corpus grades. Adam decides.*
